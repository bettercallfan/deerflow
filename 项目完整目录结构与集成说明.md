### 2.2 后端关键数据流

```
请求 → nginx(3222) → Gateway(3218) → 各 router 处理
                                         │
                    crawler.py ──── HTTP ──→ Crawler Backend(8000)
                    data_center.py ──→ sources.json（本地注册表）
                    data_center.py ──→ Elasticsearch（ES索引查询）
                    models.py ──→ config.yaml（模型配置）
```

### 3.2 前端核心架构

```
数据流：
  React Query Hooks ←→ API functions ←→ HTTP fetch
       ↕
  UI Components (useState + props)

页面路由 (App Router)：
  /                        → landing page
  /workspace               → 工作区首页
  /workspace/chats         → 对话列表
  /workspace/chats/[id]    → 对话详情
  /workspace/agents        → 智能体列表
  /workspace/data-center   → ★ 数据中心（数据源 + 上传 + 爬取）

侧边栏导航：
  workspace-nav-chat-list.tsx
    ├── /workspace/chats         → "对话"
    ├── /workspace/agents        → "智能体"
    └── /workspace/data-center   → "数据中心"
```

### 6.3 关键技术点

1. **为什么 Gateway 用 HTTP 转发而不是直接导入代码？**
   - Crawler Backend 有独立依赖（Playwright、Chromium、transformers），与 DeerFlow Gateway 环境不同
   - HTTP 转发保持松耦合，Crawler Backend 可独立升级、独立扩容
   - Gateway 的 Pydantic 模型定义了前端所需的接口契约

2. **Crawler Backend 的 LLM 模型配置为什么不在 .env 里？**
   - 原系统设计为多租户/动态配置，模型配置通过 REST API 写入 SQLite 数据库
   - 首次启动后必须调用 `PUT /api/v1/model-configs/crawler_agent` 配置 LLM

3. **Docker 内网通信**
   - gateway 通过 `crawler-backend:8000`（Docker 服务名）访问 Crawler
   - 通过 `CRAWLER_BACKEND_URL` 环境变量配置，在 docker-compose 中注入
   - 开发环境暴露端口 `8000:8000` 便于直接调试

4. **前端布局统一**
   - 三个 Tab（数据源/上传/爬取）共享同一个 `<aside>` + 右栏布局框架
   - 标题栏始终显示 "数据中心"
   - "+" 按钮行为随 Tab 切换（上传文件 / 新建爬取任务）
   - 卡片样式统一（`rounded-2xl border px-4 py-4`）

## 八、常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 502 Bad Gateway | nginx 缓存了重启后容器的新 IP | `docker restart chenruofan-deer-flow-nginx` |
| 爬取任务永远是 PENDING | Crawler Backend 未配置 LLM | 执行 `curl PUT model-configs/crawler_agent` |
| 数据中心页报错 | data-center-page.tsx JSX 括号不匹配 | 检查 `{condition ? (...) : (...)}` 中 `)}` 是否在闭合标签之前 |
| Crawler Backend 起不来 | Playwright 系统依赖缺失 | 检查 Dockerfile 中 `apt-get install` 的 Chromium 依赖列表 |
