crawler_agent_backend 代码整体逻辑结构分析
一、项目定位
这是一个基于 LLM 的智能爬虫后端服务，核心能力是：给定一个网站入口 URL 和自然语言查询（如"提取所有产品价格"），通过 LLM Agent 驱动浏览器自动导航、采集页面，再通过 LLM 递归解析 HTML 提取结构化数据（JSON/Markdown），最终写入外部存储（MySQL 或 Milvus 向量库）。支持一次性任务和定时任务两种模式。

四、核心数据流（一次性爬取任务）

POST /api/v1/crawl/tasks
  { name, portal_url, query, output_mode, json_schema, storage_db_type }
        │
        ▼
  ① ModelConfigService.ensure_output_mode_ready()
     验证 LLM 配置是否就绪（JSON 模式需要 2 个模型，Markdown 需要 1 个）
        │
        ▼
  ② CrawlService.create_task() → 写入 CrawlTask (dedup_enabled=False)
  ③ CrawlService.create_run()  → 写入 CrawlRun (status=PENDING)
        │
        ▼
  ④ TaskExecutor.submit(run_task_blocking)
     通过 asyncio.Semaphore(2) 限制并发
        │
        ▼
  ⑤ CrawlService.execute_task_sync()  ← 核心执行循环
     ├── 加载 LLM 模型配置
     ├── 【阶段1：导航】调用 legacy_bridge.collect_pages_sync()
     │     → BrowserAgent(LLM) + Playwright MCP 驱动浏览器
     │     → 点击、翻页、找到目标页面
     │     → 返回候选页面列表 [{url, title, html}]
     │
     ├── 对每个候选页面：
     │   ├── 计算 raw_html_hash + normalized_content_hash
     │   ├── 去重检查（仅定时任务启用，手动任务跳过）
     │   ├── 【阶段2：提取】
     │   │   ├── output_mode="markdown" → ReaderLM(本地模型) HTML→MD + OCR
     │   │   └── output_mode="json"     → HTMLRecursiveExtractor
     │   │         递归遍历 HTML 树，LLM 决策提取哪些子树的字段
     │   ├── 保存 CrawlPage + CrawlResult
     │   └── 【阶段3：外部写入】StorageService.write_to_external_storage()
     │         ├── MySQL → 动态建表，INSERT 行
     │         └── Milvus → 文本分块 → fake_embedding → 向量入库
     │
     └── 更新任务/运行状态 → SUCCEEDED / FAILED

五、定时任务流程

POST /api/v1/schedules
  { schedule_type(cron/interval), payload, change_detection_enabled, ... }
        │
        ▼
  ScheduleService.create_schedule()
    ├── 写入 CrawlSchedule (status=ACTIVE)
    └── APScheduler 注册 job → build_trigger()
        │
        ▼
  触发时 → run_schedule_job(schedule_id)
    └── ScheduleService.prepare_schedule_run()
          ├── 创建 CrawlTask (source="schedule", dedup_enabled=True)
          ├── 创建 CrawlRun
          └── executor.submit(run_task_blocking)
                │
                ▼
          execute_task_sync()  同手动任务流程，但额外：
            ├── 变更检测：获取 portal_url 快照 → site_quick_hash
            │     与上次 SiteCheckpoint 对比 → 无变化则 SKIPPED_NO_CHANGE
            ├── 去重启用：按 task 级别哈希去重
            └── 提取位置缓存：URL 结构匹配 → 复用上次的 CSS/tag 路径
                  跳过 LLM 树遍历，直接提取已知位置的数据
六、关键设计决策
方面	决策
新旧隔离	旧版 crawler_agent/ 完全不修改，通过 legacy_bridge/ 桥接，视为只读第三方库
两级 LLM	第一级 BrowserAgent 导航（找页面），第二级 HTMLRecursiveExtractor 提取（解析内容）
元数据存储	所有任务/定时/页面/结果/配置 存 SQLite (crawler_agent_meta.db)，提取出的数据写外部 MySQL/Milvus
去重策略	手动任务不去重（dedup_enabled=False），定时任务按 URL+HTML 的 SHA256 哈希去重
并发控制	asyncio.Semaphore(2) 限制同时最多 2 个后台爬取任务
变更检测	定时任务执行前先快照 portal_url，与 SiteCheckpoint 比对，无变化跳过
提取缓存	JSON 模式的定时任务缓存上次成功的提取路径，同结构 URL 直接复用，跳过 LLM 调用

九、核心模块依赖关系

CrawlService (爬取编排核心)
  ├── 依赖 ModelConfigService  (LLM 配置校验)
  ├── 依赖 StorageService      (外部存储写入)
  ├── 依赖 legacy_bridge       (旧版引擎桥接)
  │     ├── collect_pages_sync()   → crawler_entrance.browse_page()
  │     ├── extract_markdown()     → ReaderLM HTML→MD
  │     └── extract_json()         → HTMLRecursiveExtractor
  ├── 依赖 hash_utils          (SHA256 去重)
  └── 依赖 url_pattern_utils   (URL 结构匹配)

ScheduleService (定时任务管理)
  ├── 依赖 CrawlService        (创建任务+运行)
  ├── 依赖 APScheduler         (定时触发)
  └── 依赖 ModelConfigService  (配置校验)
总结：这是一个设计清晰的分层架构系统，核心创新在于将 LLM 用于两个关键环节——浏览器导航和信息提取——并通过去重、变更检测、提取路径缓存等机制优化了定时重复爬取的效率。
