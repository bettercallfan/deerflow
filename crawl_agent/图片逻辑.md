爬取过程中的截图/图片处理逻辑
整个系统的图片处理分为两个独立层面：LLM 浏览器截图（辅助导航决策）和页面图片 OCR 提取（数据采集）。两者用途不同，数据流也不同。

一、浏览器截图（给 LLM 看的，导航用）
代码位置：browser_agent.py:243-358


每个推理步骤前自动触发
        │
        ▼
① browser_snapshot (MCP)  → 获取页面的可访问性树文本
② browser_take_screenshot (MCP)
     ├── fullPage: true       # 截整个页面，包括折叠部分
     ├── type: "png"
     └── 保存到临时文件: .playwright-mcp/crawler_agent_shots/page_<uuid>.png
        │
        ▼
③ 读取 PNG 文件 → Base64 编码
④ 组装成多模态消息发给 LLM：
     ├── TextBlock: 过滤后的文本快照（图片 base64 已被替换为 [图片已移除]）
     └── ImageBlock: Base64 PNG 图片
        │
        ▼
⑤ LLM 用这个截图 + 文本 判断：哪些内容符合要求、该不该点、该保存哪个页面
⑥ post_reasoning 钩子：从记忆里移除这条观察消息，防止上下文膨胀
关键点：

截图是 PNG 格式，整个页面 fullPage
临时文件不会主动删除，会堆积在 .playwright-mcp/crawler_agent_shots/ 目录下
截图不持久化到数据库，仅在 LLM 推理时作为视觉上下文使用
如果截图失败，系统优雅降级为纯文本模式
二、页面保存（save_url）
代码位置：tool.py:262-351

LLM Agent 判断页面有价值后调用 save_url(url)：

通过 browser_evaluate 执行 JS document.documentElement.outerHTML 获取完整 DOM
存在内存列表 _collected_pages 里，字段：url、title、html、html_hash
HTML 里的 <img> 标签原样保留（含 src），但不下载图片文件本身
最终存入数据库 CrawlPage.html_content 字段
三、Markdown 模式：OCR 提取图片中文字
代码位置：readerlm.py

这是图片信息真正被"提取"的环节：


HTML 页面
    │
    ▼
① clean_html() → 清洗掉 style/script/svg/iframe，将 <img src> 解析为绝对 URL
    │
    ▼
② ReaderLM 模型 HTML→Markdown
   指令要求："保留所有图片链接，使用完整绝对 URL，不要省略图片"
   输出: ![alt](https://example.com/image.png) 格式
    │
    ▼
③ extract_markdown_images() → 正则提取所有 ![alt](url)
    │
    ▼
④ ocr_image_with_qwen() → 对每个图片 URL 调用 Qwen-VL OCR 模型
   - "你是 OCR 助手。从图像中准确提取所有可见文本。"
   - 最多重试 3 次，指数退避
    │
    ▼
⑤ enrich_markdown_with_ocr() → 在 Markdown 每个图片下插入 OCR 结果
   原始: ![logo](https://x.com/logo.png)
   增强后:
   ![logo](https://x.com/logo.png)
   
   > [图片OCR结果]
   > "公司名称 XXX 科技有限公司"
    │
    ▼
⑥ 存入 CrawlResult.result_markdown_ocr
关键： OCR 提取的是图片中的文字，结果作为纯文本附加到 Markdown 里。图片二进制文件本身不下载、不存储。

四、JSON 模式
代码位置：recursive_acquisition.py

使用 crawl4ai 的 DefaultMarkdownGenerator 做 HTML→Markdown 转换
HTMLRecursiveExtractor 在 DOM 树上递归遍历
完全处理文本节点，不处理图片
<img> 标签仅作为普通节点被遍历，不看 src 属性
五、总结对比
环节	处理方式	用途	持久化？
浏览器截图	fullPage PNG → Base64 → LLM 多模态消息	帮 LLM 判断导航方向	否，推理后丢弃
save_url	保留 <img> 标签在 HTML 字符串中	保存页面原始 HTML	是，存 DB
ReaderLM HTML→MD	保留 ![alt](绝对URL)	Markdown 内容	是，存 result_markdown
OCR (Qwen-VL)	从图片 URL 读取，提取文字	把图片里文字转成文本	是，存 result_markdown_ocr
JSON 提取	忽略图片	结构化数据	不处理
一句话总结： 截图是给 LLM "看"的（导航决策），不存储。页面里的图片通过 OCR 把文字提取出来存到 Markdown，但图片文件本身从头到尾不下载、不落盘。
